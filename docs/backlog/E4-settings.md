# E4 — Settings

**Phase:** 4 · Requested by the user; **absent from the design doc's milestones**

## Starting position

The model already exists and is unused. `GameSettings` in
`Persistence/PlayerProfile.cs` carries `MasterVolume`, `MusicVolume`, `SfxVolume`
and `Haptics`; `GameBootstrap` reads it once at boot and calls
`audioManager.SetVolumes(...)`; `IAudioService.SetVolumes` is implemented with a
correct linear→dB curve.

What is missing is everything that would let a player change any of it:
**`MarkDirty` and `Save` have zero call sites outside `JsonSaveService` itself.**
So this epic is mostly wiring, not construction.

---

### STORY-4.1: Settings screen
- AC1 Generated by `SceneScaffolder` like every other screen — not hand-authored.
- AC2 Reachable from MainMenu and from in-match.
- AC3 Tabs or sections: Audio, Gameplay, Accessibility.
- AC4 Renders correctly at six-seat portrait on the narrowest supported device.

**L**

### STORY-4.2: Persist changes
- AC1 Sliders write `GameSettings` and call `MarkDirty`.
- AC2 Settings survive a restart, and an unclean quit (`GameBootstrap` already
  flushes on iOS pause and quit).
- AC3 A corrupt profile falls back to defaults and says so once.
- AC4 Volume changes apply live, with a preview sound per category.

**M**

### STORY-4.3: Display name
`PlayerProfile.DisplayName` exists and is ignored — both `MatchFactory
.DefaultNames` and `MatchLauncher` hard-code `"Player 1..N"`, so the standings
rail always shows generic names even online.

- AC1 The player can set a display name.
- AC2 It is used for their seat in hot-seat and online.
- AC3 Empty or whitespace falls back to a seat default.
- AC4 Online, the name travels to the host via `RegisterIdentityRpc` (a
  protocol change) and is treated as **untrusted client input** — length-capped
  and sanitized server-side before it reaches the rail.

**M**

### STORY-4.4: Gameplay options
- AC1 Animation speed, including an instant option.
- AC2 Confirmation prompts on commit toggle.
- AC3 Every option is presentation-only and can never change a rules outcome.

**M**

### STORY-4.5: Accessibility
- AC1 Text scale.
- AC2 Reduced motion, honoured by **every** animation added in E3 — enforced by
  routing all tweens through one service rather than by diligence.
- AC3 Colour-blind-safe dice: pip shape and layout, not colour alone. `DieView`
  currently distinguishes idle / selected / spent by colour only.
- AC4 Colour-blind-safe affordability on market cards — same issue in
  `CardButtonView`.

**L**
